## ۱. خلاصهٔ یک‌صفحه‌ای

1. **محصول چیست:** یک نرم‌افزار ویندوزی فارسی که فایل صوتی جلسه را می‌گیرد و در نهایت **صورت‌جلسهٔ رسمی + فهرست مصوبات + اکشن‌آیتم‌های دارای مسئول و ددلاین** تحویل می‌دهد. تمام پردازش سنگین روی کامپیوتر خود کاربر انجام می‌شود (بدون ارسال صدا به اینترنت).
2. **الان کجاست:** «موتور» (بخش هوش مصنوعی، بدون رابط گرافیکی) ساخته شده و **واقعاً کار می‌کند**: روی یک فایل صوتی واقعی، صدا را پاک‌سازی می‌کند، گویندگان را از هم جدا می‌کند، متن را می‌نویسد و با نام گویندگان تحویل می‌دهد. اما «رابط دسکتاپ» فعلاً فقط اسکلت است و کاربر عادی نمی‌تواند از آن استفاده کند.
3. **پیشنهاد من:** تکمیل رابط دسکتاپ (فاز M1) ← ساخت ساختار نگهداری جلسه‌ها (M2) ← تولید صورت‌جلسه و اکشن‌آیتم با مدل زبانی (M3) ← اندازه‌گیری کیفیت (M4) ← بسته‌بندی نصب‌شدنی (M5) ← بهینه‌سازی (M6) ← نسخهٔ ۱.۰ (M8).
4. **هزینهٔ تخمینی تا نسخهٔ ۱.۰:** حدود **۳۸ تا ۶۲ روز-نفر** کار ⇒ حدود **۴ تا ۶ ماه** با کار نیمه‌وقت، یا **۲ تا ۴ ماه** تمام‌وقت.
5. **پنج تصمیم نیازمند نظر شما:** ترتیب فازها، انتخاب مدل زبانی (محلی/ابری/ترکیبی)، روش توزیع و نصب، ماندن یا تغییر مدل تشخیص گفتار، و سیاست دادهٔ کاربران.
6. **ریسک اصلی:** کیفیت متن روی صدای نویزی و جلسه‌های چندنفره با گفتار هم‌زمان — و در گام صورت‌جلسه، احتمال «ساختن» عدد/نام که در جلسه گفته نشده (توهم‌زایی مدل زبانی).

## ۲. مسئلهٔ واقعی که حل می‌کنیم

**درد:** جلسهٔ فارسی ضبط می‌شود، اما تبدیل آن به متن و سپس صورت‌جلسه و پیگیری مصوبات، دستی، زمان‌بر و پرخطاست. ابزارهای موجود یا فارسی را ضعیف پشتیبانی می‌کنند، یا متن خام می‌دهند (بدون تفکیک گوینده)، یا داده را به سرویس ابری می‌فرستند (که برای جلسه‌های داخلی سازمان‌ها قابل قبول نیست).

**کاربر هدف (به‌ترتیب اولویت):**

| # | کاربر | چه می‌خواهد | چرا این محصول |
| :---: | :--- | :--- | :--- |
| ۱ | مدیر/دبیر جلسه | صورت‌جلسه و پیگیری مصوبات بدون تایپ دستی | ارزش اصلی در همین مرحله است |
| ۲ | تحلیلگر/کارشناس | متن دقیق با نام گوینده و تایم‌استمپ | برای بازخوانی و استناد |
| ۳ | کاربر حساس به محرمانگی | پردازش کامل روی دستگاه خودش | هیچ صدایی بیرون نمی‌رود |

**معیار موفقیت محصول:** یک فرد غیرفنی روی ویندوز، بدون ترمینال، یک فایل جلسه را بدهد و خروجی‌ای بگیرد که بتواند با ویرایش سبک، آن را به سازمان بفرستد.

## ۳. دارایی‌های موجود (چه چیزی الان واقعاً کار می‌کند)

این‌ها نه «طرح» هستند و نه «ادعا» — با اجرای واقعی تأیید شده‌اند:

| دارایی | شاهد |
| :--- | :--- |
| موتور ۵ مرحله‌ای: پاک‌سازی صدا ← تفکیک گوینده ← رونویسی ← ادغام ← خروجی | اجرای واقعی روی یک فایل ۳۰ ثانیه‌ای فارسی ⇒ ۹ قطعه کلامی با نام گوینده و کد خروج موفق |
| «حالت ماشین» برای اتصال به برنامهٔ گرافیکی | خروجی رویدادی (پیشرفت/لاگ/خروجی/پایان)، صفر خط نامعتبر |
| سلامت‌سنجی قبل از اجرا | بررسی خودکار مدل‌ها و ابزارهای لازم ⇒ نتیجهٔ «آماده» |
| تست خودکار | ۱۰ تست پایتون + ۳ تست سی‌شارپ، همه سبز؛ بیلد برنامهٔ گرافیکی بدون هشدار |
| پشتیبانی نوشتاری فارسی | فاصله‌گذاری، نیم‌فاصله، واژه‌نامهٔ تخصصی قابل ویرایش |
| اسکلت برنامهٔ گرافیکی | معماری استاندارد + پیدا کردن خودکار موتور + اجرای فرآیند |
| استفاده از مدل‌های موجود | مدل‌ها بدون دانلود دوباره از پروژهٔ قبلی استفاده می‌شوند (حدود ۱.۶ گیگابایت) |
| مستندات و خودکارسازی | مستندات کامل معماری/عملیات/کیفیت + مهارت‌های نوشتاری عامل هوشمند |

**آنچه وجود ندارد و باید ساخته شود:** اتصال رابط کاربری به اجرای واقعی، نگهداری و آرشیو جلسه‌ها، تولید صورت‌جلسه با مدل زبانی، اندازه‌گیری کیفیت، و نصب‌کننده.

## ۵. پنج تصمیم که نظر شما را می‌خواهم

### D1 — ترتیب ارزش: اول رابط گرافیکی یا اول صورت‌جلسهٔ هوشمند؟

| گزینه | فایده | هزینه/ریسک |
| :--- | :--- | :--- |
| **الف) رابط گرافیکی اول (توصیهٔ من)** | بازخورد واقعی از کاربر، جذابیت دیدنی، قالب تحویل | رسیدن دیرتر به ارزش اصلی (صورت‌جلسه) |
| ب) صورت‌جلسهٔ هوشمند اول | سریع‌تر به خروجی «واو» و ارزش اصلی | فقط برنامه‌نویس می‌تواند امتحانش کند |
| ج) موازی | سرعت بیشتر | تمرکز کمتر، دو مسیر نیمه‌تمام |

### D2 — مدل زبانی: محلی، ابری، یا ترکیبی؟

| گزینه | هزینه | محرمانگی | کیفیت صورتی‌جلسه |
| :--- | :--- | :--- | :--- |
| **الف) محلی (توصیهٔ من به‌عنوان پیش‌فرض)** | صفر ریالی، نیازمند کارت گرافیک قوی | کامل | متوسط (مدل‌های ۷۰ میلیاردی برای فارسی هنوز ضعیف‌تر از ابری‌ها) |
| ب) ابری | تقریبی **۵ تا ۳۰ سنت برای هر جلسهٔ یک‌ساعته** (بسته به مدل و طول متن) | متن جلسه از دستگاه خارج می‌شود | بهترین |
| ج) ترکیبی (توصیهٔ نهایی من) | صفر تا همان چند سنت | پیش‌فرض کامل محلی؛ ابری فقط با انتخاب صریح و هشدار | کاربر بر اساس حساسیت جلسه انتخاب کند |

> عدد هزینه تخمینی و بر پایهٔ متن حدود ۲۰ هزار توکن ورودی و ۴ هزار توکن خروجی برای یک جلسهٔ یک‌ساعته است؛ قیمت‌ها باید در زمان تصمیم دوباره بررسی شوند.

### D3 — توزیع: کاربر باید پایتون نصب کند یا نه؟

| گزینه | تجربهٔ کاربر | هزینهٔ ساخت |
| :--- | :--- | :--- |
| الف) نیازمند پایتون | بد (کاربر غیرفنی نصب نمی‌کند) | کم |
| **ب) نسخهٔ بسته‌بندی‌شدهٔ آماده (توصیهٔ من)** | نصب مثل هر برنامهٔ ویندوزی | ۶–۱۰ روز-نفر + حجم بستهٔ بزرگ‌تر (مدل ۱.۶GB جداگانه دانلود شود) |
| ج) اجرای موتور روی ماشین دیگر/سرور | خوب برای تیم | نیازمند زیرساخت، از دامنهٔ فعلی خارج است |

### D4 — مدل تشخیص گفتار: همین بمانیم یا عوض کنیم؟

| گزینه | فایده | هزینه/ریسک |
| :--- | :--- | :--- |
| **الف) ماندن روی مدل فعلی `large-v3-turbo` (توصیهٔ من)** | کار می‌کند، سرعت متعادل، فارسی قابل قبول | هیچ |
| ب) آزمودن مدل دقیق‌تر/سبک‌تر | ممکن است دقت یا سرعت بهتر شود | نیازمند دادهٔ مرجع و زمان اندازه‌گیری (فاز M4) |
| ج) مدل ابری تشخیص گفتار | دقت بالا | نقض محرمانگی کامل‌محلی |

**قاعده‌ای که پیشنهاد می‌کنم تصویب شود:** تغییر مدل فقط با عدد؛ یعنی هیچ‌کس مدلی را عوض نکند مگر بنچمارک نشان دهد بهتر شده است.

### D5 — دادهٔ کاربران: کاملاً محلی یا به‌اشتراک‌گذاری برای بهبود؟

| گزینه | فایده | ریسک |
| :--- | :--- | :--- |
| **الف) کاملاً محلی (توصیهٔ من)** | اعتماد کامل، قابل فروش به سازمان | بهبود کندتر کیفیت |
| ب) اشتراک ناشناس با رضایت صریح | بهبود سریع‌تر | پیچیدگی حقوقی و اعتماد |
| ج) اشتراک پیش‌فرض | — | از نظر من غیرقابل‌دفاع برای جلسه‌های داخلی |

## ۹. خارج از دامنهٔ فعلی (پیشنهاد می‌کنم الان وارد نشویم)

- ضبط مستقیم از میکروفون داخل برنامه (فعلاً فقط فایل صوتی).
- ترجمهٔ هم‌زمان یا زیرنویس زنده.
- تشخیص گوینده بر پایهٔ «ثبت صدای بلندمدت» افراد.
- سرویس ابری چندمشتری.
- نسخهٔ مک/لینوکس.

## ۱۰. درخواست مشخص من از شما

1. **پاسخ به پنج تصمیم D1 تا D5** (بخش ۵) — با دلیل، حتی مخالف توصیهٔ من.
2. **تأیید یا رد این سه فرض:** (الف) کارت گرافیک NVIDIA در دسترس است؟ (ب) معمولاً چند نفر و چه نوع صدای جلسه دارید؟ (ج) آیا محدودیت محرمانگی سازمانی دارید که مدل ابری را حذف کند؟
3. **تأیید ترتیب فازها** (بخش ۴) یا پیشنهاد ترتیب دیگر.
4. اگر تجربهٔ مشابه دارید: **کدام بخش از این نقشه راه در عمل بیشترین وقت را می‌برد؟** (به‌ویژه بسته‌بندی برنامهٔ ویندوزی و تولید صورت‌جلسهٔ قابل‌اعتماد)

**پاسخ‌ها را در همین قالب بدهید کافی است:**

```
D1: الف/ب/ج — دلیل:
D2: الف/ب/ج — دلیل:
D3: الف/ب/ج — دلیل:
D4: الف/ب/ج — دلیل:
D5: الف/ب/ج — دلیل:
گرافیک NVIDIA: دارد/ندارد/نمی‌دانم
اندازهٔ جلسهٔ معمول: ... نفر، مدت ... دقیقه، نوع صدا: ...

```

| **صورت‌جلسه** | سند رسمی جلسه: حاضرین، موضوع‌ها، مصوبات، پیگیری‌ها. |
| **اکشن‌آیتم** | کار مشخصی که یک نفر باید تا یک زمان انجام دهد. |
| **WER** | شاخص خطای متن: درصد واژه‌هایی که نسبت به متن مرجع درست نبوده‌اند. کمتر = بهتر. |
| **DER** | شاخص خطای گوینده: درصد زمانی که برچسب گوینده اشتباه بوده است. کمتر = بهتر. |
| **RTF** | نسبت زمان پردازش به مدت صدا. مثلاً ۰.۲ یعنی پردازش یک‌پنجم مدت صدا طول کشیده. کمتر = بهتر. |
| **مدل زبانی / LLM** | مدل هوش مصنوعی‌ای که متن می‌فهمد و می‌نویسد؛ در این پروژه از آن برای تبدیل متن خام جلسه به صورت‌جلسه استفاده می‌شود. |
| **مدل محلی** | مدل روی همان کامپیوتر اجرا می‌شود؛ داده بیرون نمی‌رود. |
| **مدل ابری** | مدل روی سرور شرکتی اجرا می‌شود؛ متن جلسه ارسال می‌شود. |
| **sidecar / نسخهٔ بسته‌بندی‌شده** | موتور پایتونی به یک فایل اجرایی ویندوزی تبدیل می‌شود تا کاربر نهایی نیاز به نصب پایتون نداشته باشد. |
| **job JSON / NDJSON** | روش گفتگوی برنامهٔ گرافیکی و موتور: درخواست به‌صورت یک متن ساختاریافته، پاسخ به‌صورت خط‌به‌خط رویداد (شروع/پیشرفت/پایان/خروجی). |
| **junction (ویندوز)** | اتصال یک پوشه به پوشه‌ای دیگر، بدون کپی کردن داده. برای استفادهٔ مشترک از مدل‌های دانلودشده. |
| **بنچمارک / مجموعهٔ طلایی** | مجموعهٔ نمونه‌های صوتی با متن و برچسب گویندهٔ دستی، برای اندازه‌گیری دقیق کیفیت. |
| **CI** | خودکارسازی: با هر تغییر کد، تست‌ها خودکار اجرا می‌شوند و اگر خراب شود جلوی ادغام گرفته می‌شود. |
| **manifest جلسه** | فایل کوچکی که مشخصات هر جلسه (عنوان، تاریخ، گویندگان، نسخهٔ مدل، فهرست خروجی‌ها) را نگه می‌دارد. |
| **فاز M1 … M8** | مرحله‌های اجرایی نقشهٔ راه. |
