## ۱. معیارها

| معیار | تعریف | ابزار | هدف |
| :--- | :--- | :--- | :--- |
| **WER** | نرخ خطای واژه = (S+D+I)/N روی متن مرجع | `scripts/evaluate.py` ⏳ | < ۱۲٪ صدای تمیز |
| **CER** | نرخ خطای کاراکتر (برای فارسی بدون فاصله‌گذاری کامل گویاتر است) | همان | گزارش همراه WER |
| **DER** | نرخ خطای تفکیک گوینده (نسبت زمان اشتباه‌برچسب‌شده) | محاسبه روی RTTM | < ۱۰٪ جلسهٔ ۴ نفره |
| **JER** | نرخ خطای قضاوت (تشخیص گفتار/سکوت) | همان | < ۵٪ |
| **Speaker count error** | اختلاف تعداد گویندهٔ تشخیص‌داده‌شده با واقعی | همان | ۰ در ۸۰٪ نمونه‌ها |
| **RTF** | زمان پردازش ÷ مدت صدا | زمان‌سنجی مراحل | < ۰.۲ (GPU) |

## ۲. نرمال‌سازی پیش از محاسبه WER

برای اینکه سنجش، هنر پالایش فارسی را جریمه نکند:

1. اعداد فارسی/عربی ⇒ یکسان‌سازی.
2. حذف علائم نگارشی.
3. اختیاری: حذف نیم‌فاصله در هر دو متن (گزارش «WER سخت» و «WER نرم‌شده» را جدا بده).
4. یکسان‌سازی «ی/ي» و «ک/ك».

## ۳. چک‌لیست پذیرش صورت‌جلسه (انسانی)

برای هر صورت‌جلسهٔ تولیدشده، این موارد را علامت بزن (هدف: ≥ ۸۰٪ در M3):

- [ ] حاضرین و غایبین درست و کاملند.
- [ ] دستور جلسه با جریان واقعی گفتگو هم‌خوان است.
- [ ] هیچ مصوبه‌ای که در جلسه توافق نشده، به‌عنوان مصوبه ثبت نشده.
- [ ] هر اکشن‌آیتم مسئول مشخص دارد.
- [ ] هر اکشن‌آیتم ددلاین مشخص دارد (یا صریحاً «نامشخص» علامت خورده).
- [ ] خروجی ملموس هر اکشن‌آیتم روشن است.
- [ ] نیم‌فاصله‌ها و نگارش فنی درست است.
- [ ] هیچ ادعای ساختگی (hallucination) دربارهٔ نام‌ها، اعداد و تاریخ‌ها وجود ندارد.
- [ ] موارد نیازمند تأیید انسانی جدا فهرست شده‌اند.

## ۴. رویهٔ سنجش

```powershell
# ۱) اجرای بنچمارک
python scripts\evaluate.py --registry data\benchmarks\registry.json --run-all

# ۲) گزارش
# data/benchmarks/reports/<تاریخ>-<device>-<compute>.md
```

هر گزارش باید شامل این‌ها باشد: `engineVersion`, نسخهٔ مدل‌ها، دستگاه، `computeType`, `beamSize`, `numThreads`, WER/CER/DER/JER، زمان هر مرحله و RTF.

## ۵. دروازهٔ رگرسیون

| تغییر | شرط پذیرش |
| :--- | :--- |
| تغییر مدل ASR یا پارامترهای Whisper | WER نباید بیش از ۱ واحد مطلق بدتر شود، مگر با تأیید صریح |
| تغییر مدل دیاریزیشن | DER بهتر یا برابر، با RTF حداکثر ۱.۵ برابر |
| تغییر پالایش/واژه‌نامه | WER نرم‌شده بهتر یا برابر + بازبینی چشمی روی ۳ نمونه |
| تغییر قرارداد (job/event) | تست‌های قرارداد C# و Python سبز + به‌روزرسانی اسناد |
| تغییر مرحلهٔ `minutes` [M3] | چک‌لیست پذیرش ≥ ۸۰٪ روی ۳ جلسه |

## ۶. ارزیابی کیفیت صورت‌جلسه (روش پیشنهادی M3)

1. سه جلسهٔ متفاوت (۲ نفرهٔ فنی، ۴ نفرهٔ مدیریتی، ۱ نفرهٔ گزارش‌دهی).
2. اجرای موتور + مهارت صورت‌جلسه.
3. دو داور انسانی چک‌لیست بخش ۳ را پر می‌کنند.
4. امتیاز = میانگین اقلام تیک‌خورده؛ اختلاف داوران > ۲۰٪ ⇒ بازبینی معیارها.
5. ثبت نتیجه در `data/benchmarks/reports/` با تاریخ و نسخهٔ prompt.
