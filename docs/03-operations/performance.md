## ۱. انتخاب دستگاه و نوع محاسبه

| سناریو | `--device` | `--compute-type` | نکته |
| :--- | :--- | :--- | :--- |
| GPU NVIDIA (عادی) | `auto` یا `cuda` | `auto` ⇒ `float16` | سریع‌ترین حالت متعارف |
| GPU با حافظهٔ کم | `cuda` | `int8_float16` | مصرف VRAM کمتر، افت اندک دقت |
| فقط CPU | `cpu` | `int8` | پایدار و بدون وابستگی |
| CPU با دقت بالا | `cpu` | `float32` | چند برابر کندتر |

`auto` برای دستگاه = CUDA اگر `ctranslate2.get_cuda_device_count() > 0` باشد، وگرنه CPU.
`auto` برای نوع محاسبه = `float16` روی CUDA و `int8` روی CPU.

اگر بارگذاری مدل Whisper روی CUDA شکست بخورد (مثلاً `cublas64_12.dll is not found`)، موتور یک بار خودکار روی CPU/int8 تلاش می‌کند و یک رویداد `log` با سطح `warning` می‌فرستد؛ دستگاه مؤثر در `session.json` ثبت می‌شود. برای اجبار به GPU، DLLهای CUDA را نصب کن.

## ۲. اهرم‌های سرعت

| اهرم | اثر | توصیه |
| :--- | :--- | :--- |
| `--beam-size` | دقت ↔ سرعت | `1` برای جلسات معمول؛ برای صدای نویزی `2`–`5` |
| `--batch-size` | throughput روی GPU (`BatchedInferencePipeline`) | `0` خاموش؛ روی GPU `۴–۸`؛ اگر OOM شد کم کن |
| `--num-threads` | ریسه‌های CPU (Whisper/ONNX) | تعداد هسته‌های فیزیکی، مثلاً `6`–`8` |
| `--num-speakers` صریح | حذف جست‌وجوی K | اگر تعداد افراد را می‌دانی، صریح بده |
| کش پیش‌پردازش | حذف تبدیل مجدد | اگر `<stem>_16k_mono.wav` موجود باشد، خودکار رد می‌شود |
| زبان صریح (`fa`) | جلوگیری از تشخیص زبان | همیشه صریح بده |
| `--chunk-seconds` / `--chunk-overlap` | حافظهٔ پایدار در جلسات طولانی | پیش‌فرض `1800`/`5`؛ برای جلسهٔ ۲ ساعته ۵ چانک |

## ۳. جدول زمان مرجع

| سخت‌افزار | ۳۰ ثانیه صدا (دیاریزیشن + ASR) | برآورد برای ۶۰ دقیقه |
| :--- | :--- | :--- |
| CPU (int8، ۶ ریسه) | ~۱۳.۷–۱۴.۷ ثانیه (preprocess ۰–۰.۴ + diarization ۱.۷–۱.۸ + ASR ۱۱–۱۳ + merge/export ~۰) | ~۲۷–۲۹ دقیقه (RTF ≈ 0.44–0.49) |
| GPU (RTX 4050 Laptop، float16) | ASR: ۱–۳.۸ ثانیه؛ کل خط لوله هنوز اندازه‌گیری نشده | هدف: RTF < 0.2 ⇒ < ۱۲ دقیقه |

> اعداد CPU از اجرای واقعی `scripts/evaluate.py` روی نمونهٔ ۳۰ ثانیه‌ای (`mm19-0062`) در ۱۴۰۵-۰۷-۲۸ ثبت شده‌اند. ASR با `beam=1` حدود ۱۱.۱ ثانیه بود؛ در آزمایش جداگانه `beam=5` حدود ۱۰.۶ ثانیه (نوسان اجرا). عدد GPU فقط مرحلهٔ ASR است و دیاریزیشن/پیش‌پردازش را شامل نمی‌شود. برای گزارش کامل و قابل مقایسه، از ستون `stageSeconds` همان گزارش استفاده کن.

## ۴. مصرف حافظه

| جزء | حافظه | نکته |
| :--- | :--- | :--- |
| Whisper large-v3-turbo (int8) | ~۱.۵ GB RAM | بارگذاری یک‌بار در ابتدای مرحلهٔ ASR |
| Whisper (float16 روی GPU) | ~۲–۳ GB VRAM | به‌همراه بافرهای CTranslate2 |
| Whisper + `batchSize=8` | +۰.۵–۱ GB VRAM | `BatchedInferencePipeline`؛ در صورت OOM خودکار به CPU برمی‌گردد |
| مدل‌های ONNX دیاریزیشن | ~۳۰۰–۶۰۰ MB RAM | CPU عادی کافی است |
| WAV پیش‌پردازش‌شده | ~۱۱۵ MB به ازای هر ساعت (16kHz مونو 16-bit) | قابل حذف پس از استخراج خروجی‌ها |

## ۵. چک‌لیست سرعت GPU

- [ ] `nvidia-smi` کار می‌کند و درایور ۵۳۰+ نصب است.
- [ ] بسته‌های CUDA پایتونی نصب‌اند (`nvidia-cublas-cu12`, `nvidia-cuda-nvrtc-cu12`) یا CUDA Toolkit 12 روی سیستم است.
- [ ] در لاگ موتور، `روی CUDA (float16)` دیده می‌شود (نه CPU).
- [ ] `--num-threads` بیشتر از هستهٔ فیزیکی نباشد (برای دیاریزیشن روی CPU اجرا می‌شود).
- [ ] اگر VRAM پر شد ⇒ `--compute-type int8_float16`.

## ۶. جلسات طولانی (M6.1)

- رونویسی برای صداهای بلندتر از `asrChunkSeconds` (پیش‌فرض ۳۰ دقیقه) به چانک‌های هم‌پوشان تقسیم می‌شود؛ مدل یک‌بار بارگذاری می‌شود و هر چانک به‌صورت WAV موقت ۱۶kHz خوانده و پس از رونویسی حذف می‌شود.
- زمان واژه‌ها و قطعه‌ها با آفست چانک تصحیح و در ناحیهٔ هم‌پوشانی بر اساس مرکز قطعه حذف تکراری می‌شوند.
- دیاریزیشن از قبل چانک ۱۰ دقیقه‌ای دارد؛ این گزینه فقط مسیر ASR را کنترل می‌کند (`۰` = خاموش).
- اعتبارسنجی: اجرای واقعی ۳۰ ثانیه با `--chunk-seconds 10 --chunk-overlap 2` (۴ چانک) بدون افت یا تکرار در خروجی نهایی.

## ۷. موازی‌سازی و کش (M6.5)

- `parallelStages: auto` (پیش‌فرض): روی CUDA دیاریزیشن (CPU/ONNX) و رونویسی (GPU) هم‌زمان اجرا می‌شوند؛ روی CPU به‌صورت ترتیبی تا ریسه‌ها با هم رقابت نکنند. با `on`/`off` می‌توان اجبار کرد.
- اندازه‌گیری ۳۰ ثانیه، CUDA float16: ترتیبی ۱۲.۹۳s در برابر موازی ۱۰.۰s ⇒ **~۲۲.۷٪ کاهش زمان کل** (شامل بارگذاری مدل).
- کش پیش‌پردازش از قبل فعال است: اگر `<stem>_16k_mono.wav` در `work/` باشد، FFmpeg دوباره اجرا نمی‌شود.
- رویدادها و پیشرفت هر مرحله ریسه-ایمن شده‌اند؛ ETA هر مرحله مستقل محاسبه می‌شود.

## ۹. ETA و تاریخچهٔ سرعت (M6.3)

- هر اجرا نسبت `stageSeconds / duration` را در `<data>/metrics/device_speed.json` ذخیره می‌کند (میانهٔ ۵ اجرای آخر، کلید `device:computeType`).
- ETA مرحلهٔ رونویسی از همان نسبت × زمان باقی‌ماندهٔ صدا محاسبه و در `stage.etaSeconds` منتشر می‌شود؛ قبل از اولین اجرا از نرخ پیش‌فرض دستگاه استفاده می‌شود.
- اندازه‌گیری ۱۴۰۵-۰۷-۲۸ روی `mm19-0062` (CPU int8): ETA اولیه ۹.۹ ثانیه در برابر ۹.۸۳ ثانیهٔ واقعی ⇒ خطای ~۰.۷٪ (هدف < ۲۰٪).
